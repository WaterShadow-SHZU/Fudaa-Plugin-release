# 验收与开发循环

## 为什么会觉得「反直觉」

Fudaa 本体很大，不能也不该整仓进 git。插件源码与可运行宿主是**分开的两棵树**。容易误以为每次改特性都要再跑一遍「从原版整树注入」。

实际分两层：

| 动作 | 何时做 | 做什么 |
| --- | --- | --- |
| **注入** | 新机器、发版、从原版重生 Canal 目录 | `inject.bat` 复制原版 → 写入插件 |
| **热构建** | 日常改菜单/导出/补丁 | `build.ps1` 只重编 jar 并拷进已有 Canal 的 `appli\app\canal\` |

验收特性时走**热构建 + 重启 GUI**，不要每次 inject。

## 单特性最小验收

1. `build.ps1` 成功，宿主 `appli\app\canal\canal-plugin.jar` 时间戳更新。  
2. `appli\appli.exe --canal-probe` → 日志 `PROBE_OK`。  
3. 正常启动，日志有 `Canal menu installed`；若动过 PIV 补丁，还有 `PivExeLauncher file:/.../piv-core-fix.jar`。  
4. 打开带 `outputs.dir` 的工程（可用原版 `examples\channel_test_case.lspiv` 的副本），点对应 Canal 菜单：  
   - 定标包：目录/tar 内恰 7 文件，`site.json` 字段合法。  
   - CSV：九列表头，无效点 `w_corr=0`。  
   - 正射 RGB：出在 `img_ortho_rgb`，未改 `img_transf`。  
   - ROI：四角顺序 SW→SE→NE→NW；GRP 往返残差说明。  
   - 核数：改核数后跑 PIV，日志出现 `PIV argv patched to ncore=...`。  
5. 原版 `Fudaa-LSPIV\` 无改动。

可选：`CanalCli selfcheck` / 各 `export-*` 做脚本回归；**最终验收仍以 GUI 菜单为准**。

## 交给另一台机器时

至少带上：

- 本仓库全文；
- 本机已有的宿主目录（或 `FUDAA_CANAL_ROOT`）；
- `docs/契约摘录.md`；
- 不要提交令牌、公网 IP、整份 Fudaa 二进制。

没有宿主 `appli` 时只能改源码与文档，不能完成本地界面验收。
